# 공개버전 정식 퍼블리싱 목표 수용 매트릭스

이 문서는 `cellpinda_gaba_sum` 공개본이 기술적으로 동작하는지와, 사업·제품·준법 승인을 위해 외부 증거가 필요한지를 한 표에서 구분한다. `PASS`는 현재 확인 가능한 증거가 있는 항목이고, `HOLD`는 코드나 자동 QA만으로 완료를 선언하지 않는 항목이다.

## 현재 기준

| 목표 요구사항 | 현재 증거 | 상태 | 최종 종료 조건 | 담당 |
| --- | --- | --- | --- | --- |
| 기존 공식 사이트와 분리된 공개본 | 별도 저장소·URL·Pages workflow | PASS | 공개 URL과 공식 URL이 계속 분리됨 | 릴리스 QA |
| 모바일에서 한 장씩 넘기는 1페이지 1메시지 | 11개 카드, 좌우 스냅, 390px 공개 URL QA | PASS (Chrome) / HOLD (실기기) | 실제 iOS·Android에서도 카드가 읽히고 넘겨짐 | UX·접근성 / QA |
| 원문·제품·후기 정보로 인한 페이지 이탈 방지 | 인페이지 `role=dialog`, 패널 내 다음 카드 CTA, 마지막 카드의 연구·제품·후기 선택지, 외부 링크는 보조 선택 | PASS (기술) / HOLD (현장) | 연구→제품→후기 흐름을 실제 상담에서 페이지 이탈 없이 완료 | 프론트엔드 / 영업 |
| 일반 GABA 연구와 제품 효능 분리 | 연구 패널 경계 문구, 번들 금지 표현 검사 | PASS | 전체 광고 인상 검토에서 암시효능 이슈 0건 | 근거·준법 |
| 사업자 발표 편의성 | 발표 모드, 첫 화면 전체 설명·제품 문의 진입 버튼, `card=1`·`card=7`, 키보드·발표자 진행 포인트 | PASS (기술) / HOLD (현장) | 실제 담당자 세션 3회에서 다음 행동 혼선 기준 충족 | 영업 / UX |
| 카드 링크 영업 공유 | 모바일 기본 공유 메뉴와 복사 fallback, 공개 URL 상호작용 QA | PASS (Chrome) / HOLD (실기기) | 실제 기기 공유 메뉴·메신저 전달 확인 | 프론트엔드 / QA |
| 제품 사실의 최신성 | 공식 저장소 B2 패킷에서 후보 표시 신호 확인, 상태 `VERIFYING` | HOLD (제한 공개 제어 PASS / 최종 승인 미확인) | 현행 판매 SKU·최종 인쇄 승인본·표시 책임자 승인 | 제품 책임자 |
| 구매자 후기 사용 | 현재 공개본은 개인 경험 안내와 보조 링크만 제공 | HOLD | 원문·이미지 권한, 작성 맥락, 경제적 이해관계 기록 | 사업·준법 |
| 실제 영업 적합성 | 세션 검증 양식, 전체·제품 우선·근거 질문 3개 시나리오, 공개 URL 자동 QA | HOLD | 실제 사업자 상담 3회, P0 오류 0건, 결과 로그 반영 | 사업·영업 |
| 전체 광고 인상 승인 | 연구·제품·후기 경계를 코드와 문서에 반영 | HOLD (기술 경계 PASS / 전체 승인 미완료) | 근거·준법 리드의 전체 페이지 최종 승인 | 근거·준법 |
| 실기기 접근성 | Chrome CDP 390px 및 공개 URL QA 통과 | HOLD | 실제 iOS·Android에서 스냅·패널·발표 모드 확인 | 릴리스 QA |

## 검증 기준 명령

```bash
pnpm run qa:public
QA_URL=https://kradavid.github.io/cellpinda_gaba_sum/ pnpm run qa:interaction
pnpm run qa:matrix
```

PowerShell에서는 공개 URL 상호작용 QA를 다음처럼 실행한다.

```powershell
$env:QA_URL = 'https://kradavid.github.io/cellpinda_gaba_sum/'
pnpm run qa:interaction
Remove-Item Env:QA_URL

# 320px·390px·1440px 매트릭스
pnpm run qa:matrix
```

## TF 사용 규칙

1. `HOLD` 항목을 기술 QA 통과만으로 `PASS`로 바꾸지 않는다.
2. 외부 증거가 들어오면 `TF_REVIEW_LOG.md`에 문제·결정·변경 파일·검증 결과·다음 액션을 남긴다.
3. 제품 표시사항이나 후기 권한이 바뀌면 공개 문구와 자동 QA를 함께 재검토한다.
4. 실제 세션 결과가 쌓이기 전에는 사업·영업 리드의 최종 승인을 표시하지 않는다.
