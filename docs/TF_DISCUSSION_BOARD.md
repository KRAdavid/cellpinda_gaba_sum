# 공개용 GABA 페이지 TF 토론 보드

이 문서는 공개 페이지를 계속 개선하기 위한 논점 대기열이다. 회의에서 의견을 나누는 것과 공개 승인을 같은 것으로 보지 않도록, 각 논점을 `질문 → 충돌하는 관점 → 필요한 증거 → 결정 → 검증` 순서로 관리한다.

실제 역할 배정은 [`TF_ROSTER.md`](TF_ROSTER.md)를 기준으로 하며, 보드의 결정권자·다음 담당자가 `미배정`이면 해당 논점은 결정하지 않고 준비 상태로 남긴다.

## 운영 원칙

- 기술 QA가 통과해도 실제 사업자 세션·제품 승인·후기 권리·실기기 증거가 없으면 현장 `PASS`로 바꾸지 않는다.
- 한 번에 가장 중요한 논점 1~2개만 결정하고, 나머지는 `관찰` 또는 `HOLD`로 남긴다.
- 논점에는 반드시 결정권자 1명과 다음 증거를 만드는 담당자를 둔다.
- 고객 이름·연락처·건강 상태·복용 약은 토론 보드나 세션 기록에 적지 않는다.
- 결정 후에는 [`TF_REVIEW_LOG.md`](TF_REVIEW_LOG.md)에 `문제 → 결정 → 변경 파일 → 검증 결과 → 다음 담당자·종료 조건`을 남긴다.

## 상태 정의

| 상태 | 의미 |
| --- | --- |
| `OPEN` | 문제나 이견을 더 구체화하는 단계 |
| `READY FOR FIELD` | 화면·관찰 항목·종료 기준이 정해져 현장 확인을 기다리는 단계 |
| `IN TEST` | 정해진 세션·기기·근거 확인을 실행 중인 단계 |
| `DECIDED` | TF가 적용·관찰·HOLD 중 하나를 결정했지만 후속 검증이 남은 단계 |
| `VERIFIED` | 정해진 종료 증거까지 확인된 단계 |

## 이번 기술 사전 검토

실제 참석자 회의가 아닌 코드·문서·자동 QA 기반의 사전 검토로 구분한다.

| 논점 | 영업 관점 | UX·근거 관점 | 기술 결정 | 현장 후속 |
| --- | --- | --- | --- | --- |
| UX-02 FAQ 답변 복사 | 질문에 답한 뒤 별도 문서로 이동하지 않고 채팅·문자로 같은 문장을 전달할 수 있어야 함 | 복사 대상은 이미 승인된 보류 문장으로 제한하고, 소비자 화면에는 숨겨야 함 | 발표 모드의 접힌 FAQ에 4개 `답변 복사` 버튼을 추가하고 카드 이동·발표 종료 때 상태를 초기화 | C 시나리오에서 실제 질문 자연스러움·오해 여부 확인 |
| SALES-01 제품 문의 후 행동 | 제품 설명 뒤 고객이 구매·문의·다음 카드 중 무엇을 선택해야 하는지 빠르게 알아야 함 | 최신 SKU·라벨 승인 전에는 구매를 권장하거나 제품 사실을 확정하지 않고, 제품 패널의 `다음 카드`와 접힌 외부 자료를 우선 유지 | 제품 패널에 확정되지 않은 구매 CTA를 추가하지 않고, B 시나리오에서 현재 `다음 카드`·외부 자료·발표 모드 공유 경계를 관찰 | 제품 사실 승인 후에만 CTA 확장 여부를 결정하고, B 세션에서 혼선 질문을 기록 |
| REL-01 모바일 발표 밀도 | 첫 카드 제목·본문이 시작 즉시 보여야 함 | FAQ를 열었을 때는 보조 정보가 화면을 차지할 수 있으므로 기본 닫힘과 첫 화면 가시성을 분리 측정 | 빈 복사 상태는 공간을 만들지 않게 하고, 320·390·1440px 자동 QA 유지 | 실기기에서 FAQ 열림 상태도 관찰 |

이번 역할별 사전 토론에서는 `SALES-01`을 추가했다. 영업 관점은 제품 문의 뒤 구매·문의 선택지를 더 직접적으로 보여 달라는 의견이었고, 근거·준법 관점은 최신 제품 사실 승인 전 확정 CTA를 넣지 말자는 의견이었다. 현재 결정은 기술 변경이 아니라 B 시나리오 현장 검증으로 두 관점을 먼저 비교하는 것이다.

기술 사전 검토의 결과는 `기술 PASS / 현장 HOLD`다. 이를 실제 사업자 평가나 최종 광고 승인으로 해석하지 않는다.

## 30분 회의 사용법

1. 회의 전: 각 담당자는 대기열의 논점 1개에만 의견·증거·반대 이유를 추가한다.
2. 0~5분: `OPEN`과 `READY FOR FIELD` 중 이번 회의에서 닫을 논점을 1~2개 고른다.
3. 5~20분: 화면·문서·세션 기록을 보며 적용·관찰·HOLD 중 하나를 결정한다.
4. 20~27분: 변경 파일, 검증 명령, 다음 담당자, 종료 조건과 이견을 기록한다.
5. 27~30분: `TF_REVIEW_LOG.md`와 수용 매트릭스에 같은 결론을 반영한다.

```text
변경 파일:

```

실제 세션 결과는 [`SALES_SESSION_VALIDATION.md`](SALES_SESSION_VALIDATION.md)에 먼저 기록하고, 요약 판단만 이 보드와 리뷰 로그에 반영한다.
