# 공개용 GABA 페이지 TF 회의 패킷

이 문서는 공개 페이지를 영업 현장에서 계속 개선하기 위한 30분 회의용 진행표다. 회의의 목적은 아이디어를 많이 내는 것이 아니라, 고객이 카드 흐름 안에서 다음 행동을 놓치지 않는지 확인하고 공개 가능한 변경만 결정하는 것이다.

## 회의 전 준비

- 공개 URL: `https://kradavid.github.io/cellpinda_gaba_sum/`
- 전체 설명 시작: `?mode=presenter&card=1#story`
- 제품 문의 우선 시작: `?mode=presenter&card=7#story`
- 최신 배포와 코드 상태: [`RELEASE_HANDOFF.md`](RELEASE_HANDOFF.md)
- 사업자 상담 직전 요약본: [`SALES_ONE_PAGE_GUIDE.md`](SALES_ONE_PAGE_GUIDE.md)
- 이전 결정과 재현 기록: [`TF_REVIEW_LOG.md`](TF_REVIEW_LOG.md)
- 현장 세션 기록: [`SALES_SESSION_VALIDATION.md`](SALES_SESSION_VALIDATION.md)

회의 전 릴리스 QA 담당자는 `pnpm run qa:public`과 가능한 경우 `pnpm run qa:matrix`의 결과를 준비한다. 실제 세션이 없는 날에는 현장 PASS를 선언하지 않고 기술 증거만 갱신한다.

## 역할별 발언 순서

| 순서 | 담당 | 반드시 답할 질문 | 결정에 쓰는 증거 |
| --- | --- | --- | --- |
| 1 | 사업·영업 리드 | 고객이 지금 무엇을 보고 다음에 무엇을 해야 하는지 바로 알 수 있는가? | A/B/C 세션 관찰, 다음 행동 혼선 |
| 2 | 소비자 UX·카피 리드 | 카드 하나에 메시지 하나인가? 일상 용어로 읽히는가? | 카드 문구, 단계 가이드, 이탈 지점 |
| 3 | 근거·준법 리드 | 연구·제품·후기 사이에 효능·안전성·상호작용이 암시되지 않는가? | 연구 출처, 제품 표시사항, 금지 표현 검사 |
| 4 | 제품 책임자 | 제품명·구성·식품 유형·섭취 정보가 최신 1차 자료로 확인됐는가? | 최신 포장·로트·제조사 자료 |
| 5 | 프론트엔드·접근성 리드 | 패널을 읽은 뒤 페이지 안에서 이어지고, 키보드·모바일 조작이 유지되는가? | 상호작용 QA, 포커스·overflow 확인 |
| 6 | 릴리스 QA 리드 | 공개 자산과 문서가 같은 버전인가? 기존 공식 사이트와 섞이지 않는가? | Pages run, 공개 URL, 번들 QA |

## 30분 진행표

### 0~3분 — 릴리스 상태 확인

- 현재 커밋, Pages 배포, 공개 URL HTTP 상태를 확인한다.
- `PASS`, `기술 PASS / 현장 HOLD`, `HOLD`를 구분한다.
- 제품 표시사항·후기 권한이 확인되지 않았으면 해당 문구를 넓히지 않는다.

### 3~10분 — 고객 흐름 검토

발표 모드에서 다음 흐름을 실제 화면으로 확인한다.

`일상 상태 → 휴식 → 성분 일반정보 → 일반 연구 → 제품 정보 → 생활 루틴 → 후기·마무리`

다음 세 질문에 답하지 못하면 UX·카피 변경 후보로 기록한다.

1. 고객이 현재 카드와 전체 흐름의 위치를 알 수 있고, `다음 카드`가 기본 행동으로 보이는가?
2. 연구·제품·후기를 외부 링크로 먼저 열지 않고 카드 안에서 이해할 수 있는가?
3. 패널을 닫거나 `다음 카드로 계속 보기`를 눌렀을 때 다음 행동이 분명하고, 공유·발표 같은 도구는 `더 보기` 뒤에 남아 있는가?

### 10~16분 — 영업 시나리오 검토

| 시나리오 | 시작점 | 통과 질문 |
| --- | --- | --- |
| A. 전체 이야기 | `card=1` | 고객이 일상 장면을 제품 효능으로 바로 해석하지 않고 07번까지 따라오는가? |
| B. 제품 문의 우선 | `card=7` | 제품 사실의 제한 공개 상태와 최신 포장 확인 필요를 이해하는가? |
| C. 근거 질문 대응 | `card=6` | 수면·스트레스·병용 질문에 미승인 효능·안전성 답변 없이 흐름을 유지하는가? |

실제 고객의 이름·연락처·건강 상태·복용 약은 기록하지 않는다. 관찰 기록은 카드 번호, 사용한 표현, 이탈 여부, 다음 행동만 남긴다.

### 16~21분 — 근거·제품·후기 게이트

- 일반 GABA 연구가 셀핀다 제품 효능의 직접 근거처럼 읽히지 않는가?
- 제품 정보가 최신 표시사항 확인 전 확정 문구로 보이지 않는가?
- 후기가 개인 경험을 넘어 효능 보장이나 재게시 자료처럼 보이지 않는가?
- 외부 링크가 필요한 경우에도 인페이지 패널이 먼저 열리는가?

하나라도 불명확하면 공개 문구를 추가하지 않고 `HOLD`로 남긴다.

### 21~26분 — 접근성·배포 확인

- 320·390·1440px에서 overflow·패널·발표 모드·카드 링크를 확인한다.
- 실제 iOS·Android 확인이 없으면 실기기 PASS로 기록하지 않는다.
- Pages의 공개 자산이 현재 코드 커밋과 일치하는지 확인한다.

### 26~30분 — 결정과 다음 액션

각 이슈는 아래 한 줄 형식으로 닫는다.

`문제 → 결정 → 변경 파일 → 검증 결과 → 다음 담당자·종료 조건`

결정은 다음 중 하나만 사용한다.

- `적용`: 공개 문구와 동작을 바꾸고 QA까지 실행
- `관찰`: 현장 세션에서 같은 문제가 반복되는지 기록
- `HOLD`: 1차 근거·제품 승인·사용권·실기기 증거가 생길 때까지 공개하지 않음

## 정식 퍼블리싱 종료 조건

다음 네 가지가 모두 채워지기 전에는 최종 사업·준법 승인으로 표시하지 않는다.

1. A/B/C 실제 사업자 세션 3회에서 P0 오류 0건
2. 최신 제품 라벨·로트·표시사항의 제품 책임자 승인
3. 후기 원문·이미지 사용권과 경제적 이해관계 확인
4. 실제 iOS·Android에서 카드 스냅·패널·발표 모드 확인
